# UNM Freedom Confessions: public website

The static site at https://unm.klasmeyt.com: home page, Privacy Policy, Terms of Use, Community rules, and the account deletion page that Google Play requires. Separate app from `mobile/` and `admin/`. It uses the same Next.js, React, TypeScript and Tailwind versions as `admin/`.

It has no database, Supabase, sign-in, cookies, analytics, environment variables or external requests. Every page is prerendered at build time.

## Run locally

1. `npm install`
2. `npm run dev`, then open http://localhost:3000.

Checks: `npm run typecheck`, `npm run lint`, `npm run build`. To test the production build, run `npm run start` after the build.

## Pages

| Route | Content |
|---|---|
| `/` | What the app is (from the PRD) and "coming soon to Google Play" |
| `/privacy`, `/terms`, `/rules` | The app's legal texts, word for word (`content/legal.ts`) |
| `/delete-account` | In-app steps, what happens, and how to request deletion by email |
| `/robots.txt`, `/sitemap.xml` | Generated by `app/robots.ts` and `app/sitemap.ts` |

## Editing the legal text

The Privacy Policy, Terms of Use and Community rules must stay **word for word the same as in the app** (`mobile/app/legal/[doc].tsx`, `DOCS`). `content/legal.ts` is a copy of that object. Never change one without the other, and never reword them only on the site.

1. Change the text in the app (it needs school approval).
2. Copy the same `DOCS` object into `content/legal.ts` as `LEGAL`.
3. Update `LEGAL_LAST_UPDATED` in the same file, and `lastModified` in `app/sitemap.ts`.

To check that the two texts are identical, run this from the repo root:

```sh
node -e "const fs=require('fs');const cut=(f,k)=>{const s=fs.readFileSync(f,'utf8');return s.slice(s.indexOf(k)+k.length,s.indexOf('} as const;'))};console.log(cut('mobile/app/legal/[doc].tsx','const DOCS = {')===cut('site/content/legal.ts','export const LEGAL = {'))"
```

The deletion page describes what `delete_my_account` does. If that function changes, update `app/delete-account/page.tsx`.

## Download links

The home page's "Get the app" block reads two constants in `site/lib/site.ts`:

- `PLAY_STORE_URL`: the app's Google Play listing.
- `APK_RELEASES_URL`: the GitHub releases page with the .apk files.

While a constant is `null`, its button is dimmed, is not a link, and has the caption "Coming soon". To turn a button on, set the URL, then commit and redeploy. The button becomes a link that opens in a new tab. When `APK_RELEASES_URL` is set, a short note on installing from GitHub also appears.

Brand rules:
- The Google Play badge (`site/public/badges/google-play-badge.svg`) is Google's official file. Use it unmodified: no recolouring, cropping, stretching, rotating or effects. Keep its aspect ratio and the clear space around it.
- The GitHub mark (`site/components/brand/github-mark.tsx`) is the official Octicon `mark-github` path, copied unchanged. Do not change its shape or proportions.

## Security headers

The headers are set in `lib/security-headers.ts`:
- `X-Content-Type-Options: nosniff`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Frame-Options: DENY`
- `Permissions-Policy` denying the camera, microphone and geolocation
- a self-only CSP with `frame-ancestors 'none'`

The pages are static, so a per-request nonce is not possible. `script-src` therefore allows `'unsafe-inline'` for Next.js's inline hydration scripts. The site loads nothing from other origins.
